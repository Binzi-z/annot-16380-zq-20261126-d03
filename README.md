# 离线值班身份签发 · 安全复核 (dutyid)

对一批**合成**值班身份签发做离线安全复核。原生 Windows、Python 3.12、**仅标准库**、
全部本地合成数据、无网络。

题面（`task/PROMPT.txt`）要求核查的核心安全属性，本工具逐条落地：

1. 申请后**先锁定**一份资源授权（绑定受托人 / 资源 / 授权代），再由**两个控制人分别签封**；
2. 签封须**限定** 受托人 + 资源 + 授权代；
3. **同一根来源的两份见证不能合并**成有效许可（原点是“根的谱系原点”，代理换根不改写历史）；
4. 管理员可能在两步之间**撤回**身份 —— 撤销必须支配任何签封；
5. 两个**真实线程 + 屏障**复现两种危险交错：
   - A：**撤销先写入**；
   - B：**合法签发已持久化、确认回执遗失**，再叠加**旧代同号重投**与**代理换根**；
6. 恢复后依据**实际落盘的签封及清单**重建授权集合，并给出**独立可验证的最小冲突证据**；
7. **小图穷举**签发 / 撤销 / 代理换根的短交错，检验不变量；
8. 六万条**按组织隔离**的身份记录，比较一次撤回的**实际访问范围**与**全量结果**。

## 快速开始

```bash
# 全量测试（推荐；在受限环境下这是唯一被允许的运行入口）
python -m unittest discover -s tests -v

# 直接运行工具（输出中文摘要 + report.json）
python -m dutyid                # 全部检查
python -m dutyid --json         # 只输出 JSON
python -m dutyid --workdir out  # 指定工作目录（需为空/干净）
```

> 说明：`build_report` **不会清理**已有工作目录，以避免误删他人数据；
> 复用脏目录（含旧代状态）会如预期地触发代回退拒绝。请用新目录。

## 模块结构

| 模块 | 职责 |
|------|------|
| `canonical.py` | 规范 JSON（键排序/无空白/禁浮点）与带域标签的 SHA-256 |
| `crypto.py` | 合成根密钥、HMAC 签封、**根谱系原点**与密钥登记表 |
| `model.py` | 事件 / 锁 / 签封 / 撤销 / 换根 / 清单 / 事实引用 |
| `store.py` | 追加式**哈希链**事件日志 + 逐签封/锁/撤销独立文件 + 清单，全部 `fsync` |
| `rules.py` | **纯**授权规则（单一事实源）：锁绑定、独立性、撤销支配、单活动代 |
| `evidence.py` | 极小违规事实子集（MUS）的构造与**独立**复核 |
| `engine.py` | 状态机 + 恢复；主动拒绝代回退与旧代重投；产出冲突证据 |
| `verify.py` | **独立验签器**（不依赖 engine）：重算 MAC/摘要/授权集合/证据极小性 |
| `scenarios.py` | 两个真实线程 + 屏障的竞态复现（A、B） |
| `modelcheck.py` | 小图有界穷举（默认深度 5）+ 安全不变量 |
| `scale.py` | 60,000 条按组织隔离记录，作用域 vs 全量对比 |

## 关键设计要点

- **独立性 = 不同控制人 且 不同根谱系原点**（缺一不可）。只看 `root_id` 字符串不够：
  同一人的两把密钥、或代理换根产生的“新根”都可能绕过。判定统一走
  `rules.independent_pair`，规则 / 证据 / 模型检查三处共用。
- **代理换根不改写历史**：新根以旧根为父，谱系原点不变；换根前落的签封仍按旧原点解释。
  因此换根后同源的两份第 2 代签封**不能**合并成有效许可。
- **撤销支配**：提交时重读落盘事实，撤销先落盘则签发被拒；恢复也以撤销覆盖为准。
- **最小冲突证据**是**极小违规事实子集**：`revoked`={锁,撤销}；见证不独立={锁,签封,签封}。
  独立验签器重算每条事实摘要、重放违规判定、并逐条删除确认不再违规（极小性）。
- **恢复只信落盘**：先校验事件哈希链，再读独立签封/锁/撤销文件与清单交叉核对；
  旧代签封与外部同号重投被忽略；清单自报与重建不符作为**语义分歧**显式检出。
- **规模隔离**：受托人姓名跨组织复用，故按 `(org, trustee)` 复合键检索才精确；
  与按姓名全局检索对比，量化“不做隔离会波及多少别的组织”。

## 验证口径

- 结构完整性（`VerifyReport.ok/problems`）：哈希链、MAC、摘要、被引文件缺失 —— 正常应为 ok。
- 语义分歧（`VerifyReport.findings`）：清单自称与重算不符 —— 这是工具**应检出**的真实问题。
- 场景 A/B 的 `expectations`：一组明确的“必须成立”断言（如“恢复后许可不在授权集合”
  “证据恰为 2/3 条事实”“旧代重投被拒”“检出陈旧清单分歧”）。
